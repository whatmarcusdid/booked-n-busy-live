# AGENTS.md — Book Service

Design rules: @DESIGN.md · Tokens: `design/tokens/tokens.json` (source) → `design/tokens/tokens.css` (generated by `python3 design/tokens/build.py`)

## Before any UI work
1. Read @DESIGN.md before creating or modifying UI. Do not rely on memory of it.
2. List the DESIGN.md rules and tokens that apply to the task before editing.
3. Check for an existing component first. Reuse or compose it; don't duplicate.

## While building
- Use only approved tokens via CSS variables (`var(--color-*)`, `var(--space-*)`, `var(--radius-*)`, `var(--shadow-*)`, `var(--typography-*-*)`).
- In the Next.js app, map Tailwind/shadcn theme values to these variables; never add arbitrary
  classes like `bg-[#34d399]` or `p-[13px]`. Use Inter for all UI text (no system-font fallback).
- Treat live-only legacy colors listed in DESIGN.md Gaps (e.g. `#1B4A41`, `#9be382`) as deprecated.
- No hardcoded colors (hex, rgb, hsl, named) and no raw px values in components. The only
  exceptions are inside `tokens/`.
- Follow the contrast table in DESIGN.md. Never use a pair marked Fail for text or icons.
- Every interactive element needs hover, focus-visible, active, and disabled states. If DESIGN.md
  doesn't define one, flag it and stop instead of inventing values.
- Use logo and graphic SVGs exported from Figma as-is. Don't redraw or recolor them.

## When guidance is missing or conflicts
- Flag missing or conflicting guidance before inventing a solution. Say what's missing, where you
  need it, and propose the options, but don't pick a new value yourself.
- Check DESIGN.md "Gaps and Open Questions" first; the item may already be known.

## Protected files
- Do not modify `design/tokens/tokens.json`, `design/tokens/tokens.css`, `DESIGN.md`, or this file unless the
  user explicitly asks. If you change tokens.json, run `python3 design/tokens/build.py` and sync the DESIGN.md front matter.

## Before finishing
- Compare your diff against DESIGN.md and report any unapproved colors, hardcoded values,
  missing interaction states, or contrast issues.
- Run `npx @google/design.md lint DESIGN.md` if DESIGN.md changed.

## Brand precedence and deprecated values
- Live site wins over Figma. If they conflict, follow tokens.json and log the Figma item under
  DESIGN.md "Update Figma to match"; don't change tokens to match Figma.
- Never use TradeSiteGenie (old brand) colors or names listed under `deprecated.*` in tokens.json /
  DESIGN.md "Deprecated" (`#1B4A41`, `#9be382`, `#1D4ED8`, `#2563EB`, beiges, `#6F797A`, the
  "TradeSiteGenie" title, etc.). When editing code that uses them, replace them with brand tokens.
- Light mode only: don't add `.dark` styles or dark variants.
- Buttons: primary = solid green with Dark BG text (incl. Sign In); secondary = outline, indigo on
  light surfaces, green only on `bg-dark`. Inputs and focus rings follow the DESIGN.md standard spec.
